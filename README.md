# HA Smart Analyst

Универсальная интеграция Home Assistant: детерминированные правила по сущностям,
журнал инцидентов, отчёты с локальными фактами и необязательным заключением
DeepSeek. Версия 1.0 ничего не включает и не регулирует: интеграция только читает
состояния (`SEC-01`).

Документ-источник требований — ТЗ v0.2 от 30.10.2026. Результаты этапа 0
(архитектурные решения, машинные схемы, макеты, эталонные данные и политика
версии HA) — в [docs/stage-0.md](docs/stage-0.md).

## Установка через HACS

1. HACS → ⋮ → **Custom repositories**.
2. URL: `https://github.com/thebestbaduser/ha_smart_analyst`, категория — **Integration**.
3. Найти «HA Smart Analyst» в HACS → **Download**.
4. Перезапустить Home Assistant.
5. «Настройки → Устройства и службы → Добавить интеграцию → HA Smart Analyst».

Обновления приходят через HACS при новых релизах — вручную ничего копировать не нужно.

### Если панель показывает старый интерфейс

После обновления перезапустите Home Assistant и обновите страницу (`Ctrl+Shift+R`).
В шапке панели видно `v<backend> · frontend <версия>`; если версии расходятся,
появится предупреждение — очистите данные сайта HA или откройте его в приватном
окне. URL модуля панели версионирован (`panel.js?v=<версия>`), поэтому после
перезапуска браузер загружает новый файл; `undefined` вместо отчёта означает,
что сервис не вернул текст — причина и этап сбоя выводятся в панели и журнале.

### Установка вручную

Скопируйте `custom_components/ha_smart_analyst` в `config/custom_components/`,
перезапустите HA и добавьте интеграцию. Без ключа DeepSeek всё работает в режиме
«локальные правила + шаблонные отчёты» (`CFG-03`).

## Что уже работает

* **Каталог и автообнаружение**: реестр сущностей/устройств/зон, поиск и фильтры,
  подсказки по системе и роли с уверенностью и причиной; догадка всегда требует
  подтверждения (`ENT-01…ENT-03`).
* **Редактор в панели**: создание систем, добавление датчиков из каталога, простое
  правило (датчик → условие → порог → длительность → восстановление), профили
  отчётов, запуск отчёта и подтверждение инцидента (`UI-03`, `UI-04`).
* **Ядро без зависимости от HA**: единицы и качество данных, модель дома,
  JSON-AST правил, трёхзначный вычислитель с `for`/гистерезисом/cooldown,
  инциденты с дедупликацией, история с покрытием, составные измерения
  (сумма, разность, среднее, масштаб), строгая валидация ответа ИИ
  и шаблонный fallback, очередь уведомлений, версионированное хранилище.
* **Отчёты по расписанию**: время, дни недели и часовой пояс HA; отчёт уходит сам,
  пропущенные запуски не догоняются пачкой. В отчёт попадают показания и история
  за период (изменение, среднее, минимум, максимум), даже если ИИ недоступен.
  Профиль задаёт обязательные показатели (они попадают в отчёт всегда), порядок,
  лимит дополнительных и группировку по системам; покрытие считается по каждому
  датчику, а покрытие системы — как среднее, а не по лучшему источнику.
  Компактный отчёт собирает связанные показатели в короткие строки (пары
  «факт/уставка», фазы, энергия, температуры); группировку можно выключить.
  Таймаут ожидания истории настраивается (1–60 с): при превышении отчёт уходит
  по текущим показаниям с явной пометкой. Если ИИ отключён вручную, отчёт так
  и пишет — «ИИ отключён», а не «не ответил»; деньги выводятся с копейками.
* **Интеграция HA**: Config/Options Flow, координатор на `state_changed`, Recorder
  в executor, атрибуты сущностей и максимальный возраст данных (`STALE`),
  диагностические сущности, кнопка проверки уведомлений, 7 сервисных действий,
  WebSocket API, панель, диагностика без секретов, RU/EN.

## Чего ещё нет (осознанно, см. stage-0)

* конструктор вложенных `AND/OR/NOT` (сейчас в панели простое сравнение одного датчика;
  произвольный AST можно сохранить через WebSocket `rule/save`);
* правка уже добавленного датчика (атрибут и максимальный возраст задаются при
  добавлении; изменить их можно только повторным добавлением);
* порядок показателей задаётся полем профиля `measurement_order` через WebSocket;
  в панели доступны обязательные/дополнительные списки без drag&drop;
* `standard`/`detailed` не используют emoji-группировку compact: это сделано
  осознанно, чтобы подробный отчёт оставался табличным;
* кнопки и команды Telegram (`/status`, `/report`, ACK из чата) — доставка через
  `notify` и постоянные уведомления уже есть;
* персональные базовые линии, аномалии и симулятор правил (P1);
* диалог на естественном языке и адаптер InfluxDB (P2);
* управление устройствами (P3, отдельный разрешительный контур).

## Проверка

```bash
# ядро и контракты, Home Assistant не нужен
python -m pytest tests -q

# интеграционные тесты HA (нужен pytest-homeassistant-custom-component)
python -m pytest tests/ha -q

# помощники панели (Node 22+, без зависимостей)
node --test tests/frontend/*.test.mjs
```

Проверено: **170 тестов ядра** и **208 тестов с Home Assistant** (0 падений) плюс
**12 frontend-тестов** в Node на Python 3.12 и Home Assistant 2025.1.4;
`ruff check` без замечаний; JSON-схемы и переводы валидны.
Эталонный дом из 18 измерений и четыре уровня отчёта зафиксированы в
`docs/fixtures/reference_home_reports.json` и проверяются тестом
`tests/test_reference_home.py`.

На Windows тестовый плагин блокирует сокеты, а ProactorEventLoop создаёт self-pipe
через `socketpair`, поэтому в `tests/conftest.py` сокеты на время создания loop
разрешаются и резолвер aiohttp заменяется на потоковый; на Linux это не требуется.

## Безопасность

* Секреты (ключ DeepSeek) живут только в Config Entry; экспорт конфигурации их вырезает.
* Правила не исполняют Python, шаблоны и произвольные URL (`SEM-07`, `SEC-04`).
* Тексты сущностей HA считаются данными, а не инструкциями для модели (`SEC-03`);
  ответ модели проверяется по схеме, ссылки `evidence_refs` обязаны разрешаться,
  неподтверждённые числа помечаются, локальные цифры рендерятся независимо от ИИ.
* Телеметрия и облачный сбор логов отсутствуют (`NFR-06`).
