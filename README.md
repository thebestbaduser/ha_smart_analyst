# HA Smart Analyst

Универсальная интеграция Home Assistant: детерминированные правила по сущностям,
журнал инцидентов, отчёты с локальными фактами и необязательным заключением
DeepSeek. Версия 1.0 ничего не включает и не регулирует: интеграция только читает
состояния (`SEC-01`).

Документ-источник требований — ТЗ v0.2 от 30.10.2026. Результаты этапа 0
(архитектурные решения, машинные схемы, макеты, эталонные данные и политика
версии HA) — в [docs/stage-0.md](docs/stage-0.md).

## Что уже работает

* **Ядро без зависимости от HA** (`custom_components/ha_smart_analyst/core`):
  единицы измерения, качество данных, семантическая модель дома, JSON-AST правил,
  трёхзначный вычислитель с `for`/гистерезисом/cooldown, инциденты с дедупликацией,
  история и её покрытие, валидация ответа ИИ, шаблонный fallback, очередь
  уведомлений, версионированное хранилище с миграциями.
* **Интеграция HA**: Config Flow и Options Flow, координатор на событиях
  `state_changed`, адаптер Recorder в executor, диагностические `sensor`/`binary_sensor`,
  сервисные действия, WebSocket API и панель с вкладками, `diagnostics` без секретов,
  переводы RU/EN, HACS-метаданные.
* **88 unit- и контрактных тестов ядра** (`pytest`, без установленного HA)
  и **7 интеграционных тестов Home Assistant** (`pytest-homeassistant-custom-component`,
  всего 95, все зелёные).

## Чего ещё нет (осознанно, см. stage-0)

* визуальный конструктор правил и профилей отчётов в панели (сейчас — API и панель
  только для просмотра);
* кнопки и команды Telegram (`/status`, `/report`, ACK из чата) — канал отправки
  работает, интерактив — следующий шаг;
* персональные базовые линии, аномалии и симулятор правил на истории (P1);
* диалог на естественном языке и адаптер InfluxDB (P2);
* любые действия управления устройствами (P3, отдельный разрешительный контур).

## Установка

1. Скопируйте `custom_components/ha_smart_analyst` в каталог `config/custom_components/`
   Home Assistant или установите репозиторий через HACS.
2. Перезапустите Home Assistant.
3. «Настройки → Устройства и службы → Добавить интеграцию → HA Smart Analyst».
4. Пройдите мастер: имя экземпляра → DeepSeek (можно пропустить) → канал уведомлений.

Без ключа DeepSeek интеграция работает в режиме «локальные правила + шаблонные
отчёты» (`CFG-03`).

## Проверка

```bash
# ядро, без Home Assistant
python -m pytest tests -q

# контракты схем и фикстур
python -m pytest tests/test_schemas.py -q

# интеграционные тесты (нужен pytest-homeassistant-custom-component)
python -m pytest tests/ha -q
```

Проверено на Python 3.12 и Home Assistant 2025.1.4 (тестовый контур). На Windows
тестовый плагин блокирует сокеты, а ProactorEventLoop создаёт self-pipe через
`socketpair`, поэтому в `tests/conftest.py` сокеты на время создания loop
разрешаются; на Linux это не требуется.

## Безопасность

* Секреты (ключ DeepSeek) живут только в Config Entry; экспорт конфигурации их вырезает.
* Правила не исполняют Python, шаблоны и произвольные URL (`SEM-07`, `SEC-04`).
* Тексты сущностей HA считаются данными, а не инструкциями для модели (`SEC-03`);
  ответ модели проверяется по схеме, ссылки `evidence_refs` обязаны разрешаться,
  неподтверждённые числа помечаются, локальные цифры рендерятся независимо от ИИ.
* Телеметрия и облачный сбор логов отсутствуют (`NFR-06`).
